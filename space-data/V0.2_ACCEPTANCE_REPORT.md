## 2. 实际测试

运行环境：Codex Cloud Linux、Python 3.12、CPU、Chromium。独立验收服务使用 `runtime/space-v02`，没有改写原有 V0.1 的实际 Session 数据库。

```bash
.venv/bin/python -m pytest -q --junitxml=artifacts/v0.2/pytest.xml
python scripts/accept_space.py --base-url http://127.0.0.1:8013 --chromium /usr/bin/chromium
```

- **47 个 pytest 测试通过**：包含原有 38 项测试和新增 9 项空间测试。覆盖原始文件 hash、重建字节一致、楼层/标题与副本排除、实例 ID 唯一、原始图层/句柄关系、嵌套 XYZ 变换、SVG 对象对应、三维未知字段、坐标往返、API 状态/过滤、模拟设备隔离、跨楼层关联拒绝、C3 事件不被自动定位等。
- **38 项真实浏览器检查通过**：鼠标滚轮、拖动平移、复位、框选、对象句柄/图层查看、CAD 图层开关、一二层不同几何、二层 PDF 提示、设备/FOV 显式模拟开关、SVG/JSON 实际下载；1440/1024/768/390px 空间页布局；C3 五页在上述四种宽度下的 20 项回归；未关联 C3 事件不进入空间 API。
- 浏览器 JavaScript 错误 **0**，加载资源 HTTP 失败 **0**，各宽度页面无横向溢出。
- C3 浏览器回归新建的 Session 和原话均明确 **SIMULATED**，实际运行手动文本→规则分析→报告链路。该回归不冒充真实现场采集，也不重复宣称本轮完成了新的 ASR/视觉模型验收。
- 测试只有 Starlette TestClient 关于 anyio BlockingPortal 的依赖弃用提示，不影响测试通过。

机器记录：`artifacts/v0.2/pytest.xml`、`artifacts/v0.2/browser/result.json`。截图：`floor-1-desktop.png`、`floor-2-1440.png`、`floor-2-390.png`、`floor-2-simulated-camera.png` 等。

验收时曾定位并修正两处问题：派生 MLINE 线条的原始实体类型需要与渲染类型区分，已加入 source_dxf_type/derived_part_index；浏览器回归脚本通过 localStorage 切换 Session 后需要真正 reload，避免同页 hash 导航保留旧状态。上述最终测试均使用修正后的代码与重新生成的数据。

## 4. 下一阶段的进入条件

二维几何与交互已可作为三维阶段的数据基础；参考图的中央模型、左控制、右统计与交互联动已记录在 `SPATIAL_DIGITAL_TWIN.md`。

准确三维建模前应确认二层资料、墙柱/门窗/楼梯语义、真实楼层标高与高度、业务区域边界及跨层控制点。当前 JSON 顶点、源参数和稳定 ID 可以直接复用；后续测量与语义数据按这些 ID 关联，不必重做本版 CAD 几何提取。没有实测信息时不能以固定默认层高、随意外观或静态效果图替代真实数字孪生。
