## 已诊断和修复

1. Hugging Face 模型文件请求收到代理 CONNECT 403。没有绕过网络策略；改用现有允许域名上的 sherpa-onnx 官方 GitHub SenseVoice 发布包，真实转录通过。
2. 最初 8kHz TTS 样例导致 VAD 漏段和明显错字；换成官方 44.1kHz MeloTTS，并为 VAD 片段添加前卷，保留轻声起始。没有用脚本文本覆盖实际 ASR。
3. 受限命令沙箱中 Starlette TestClient 的跨线程事件循环在启动前挂起；相同测试在允许本机通信的执行上下文通过，未删除或跳过断言。
4. 手机宽度下网格受音频/文件控件最小尺寸撑开：改为允许收缩的网格轨道，390px 无横向溢出。
5. 新 Session 显示上一个任务完成状态：切换时清空任务展示，创建过程中暂停资料操作；测试不再将旧成功状态作为新任务完成证据。
6. 手动上传内置模拟文件可能进入普通 Session：按媒体 SHA 校验其来源，自动保留 SIMULATED 标记。
7. 重复安装时 TTS 随机噪声让转录出现漂移，导致“腰部”语义验证真实失败。关闭演示合成的随机噪声并固定生成参数；连续两次生成音频 SHA-256 相同，重新运行 30 项测试全部通过，未放宽 ASR 断言。

## 未验证或仍有限制

- **真实 LLM API 未调用**：未配置密钥。HTTP 请求/响应结构用 mock 验证，错误凭据/缺失密钥和伪造引用有测试；不能把这些测试称为真实模型语义验证。当前现场可运行版本默认规则报告。
- **ASR 有错字**：例如“上坡”被识别为“涨坡”、“走久”变成“我久”，第四句也有误识别。保留真实输出；可回听、人工补录，不声称转录准确率已达生产标准。
- **说话人区分未启用**：本地输出 unknown/null；不伪造 speaker1/speaker2。脚本角色仅属于 fixture/人工输入。
- **专属动作不自动识别**：穿戴、调腰带、上坡来自人工/SIMULATED 情境。基础静止/位移是姿态启发式；视频样例的平移不证明真实步态能力。
- **跨模态只有时间关联**：不能确认同一人或因果。独立录制需手动校准偏移；没有逐字强制对齐。
- **实时能力为预览、录制和事件广播**：音视频停止录制上传后再分析；没有完成低延迟连续摄像头 + 分块流式 ASR。
- **Windows / RTX 5070、USB、RTSP、实体麦克风、真实 Qwen 服务**：提供接口及部署说明，未在云端模拟成已实测。
- 主题/情感/意图基线依赖产品规则，不能全面理解反讽和跨句语义。单场体验不能推出人群趋势；优先级及改进建议是待实验验证的假设。
- Markdown 导出已验证；未实现 PDF 导出。
