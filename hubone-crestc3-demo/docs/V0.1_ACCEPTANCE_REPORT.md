### 3.3 Session 与时间戳

真实媒体 Session：`00b2163a555b451a8e9f250fe93548c3`。

声明的视频起点偏移为 2.5 秒，音频起点偏移为 1.25 秒。逐事件检查：

```text
video.timestamp = video.evidence.media_time + 2.5
audio.timestamp = audio.evidence.start + 1.25
audio.metadata.end_timestamp = audio.evidence.end + 1.25
```

例如音频片段为文件时间 0.150–5.592 秒，对应 Session 时间 **1.400–6.842 秒**；视频第一次人体事件为文件时间约 3.7333 秒，对应 **6.2333 秒**。所有原始事件 session_id 一致，文件时间范围有效，关联视频事件都落在原话区间前后 3 秒窗口内。

事件到媒体的回放使用文件时间，不把 Session 偏移重复叠加。页面重载会回显实际视频/音频偏移 2.5 / 1.25，而不是误显示 0。

边界：当前视频时间仍以帧编号/FPS 计算。本轮素材为 CFR；手机 VFR、剪辑时间跳变、长录音漂移、不同设备自动对时、逐字强制对齐**未验证**。本轮没有证明人物身份相同或事件存在因果关系。

原始记录：[验收结果](../artifacts/v0.1/acceptance-result.json)、[事件](../artifacts/v0.1/real-events.json)、[真实媒体报告](../artifacts/v0.1/real-report.md)。

## 4. 严格区分资料来源与算法方法

这三个名称不能被错误地当作同一维度：真实模型可以处理模拟输入，规则也可以处理真实录音。

| 情形 | input_origin | processing_method | 含义 |
|---|---|---|---|
| 模拟视频上的 YOLO / 模拟音频上的真实 ASR | SIMULATED | REAL_MODEL | 算法真实执行，资料仍是合成 |
| fixture 直接读取预设转录、预设动作脚本 | SIMULATED | SIMULATED | 不是模型识别 |
| 已校验真实参考视频上的人体检测、真人 ASR | REAL_RECORDING_REFERENCE | REAL_MODEL | 真实参考资料 + 模型推理 |
| 区域进入、静止/位移规则、情感/关键词/主题 | 对应原资料 | RULE_BASED | 从原始证据按规则派生，不冒充动作模型 |
| 产品规则报告 | EVIDENCE_DERIVED 或 SIMULATED | RULE_BASED | 固定规则与建议模板，不是 LLM |
| 配置并真实调用 LLM 后的洞察 | EVIDENCE_DERIVED 或 SIMULATED | REAL_MODEL | 仍是待验证研究假设 |
| 人工转录、人工观察 | MANUAL 或对应资料 | MANUAL | 不冒充 ASR / CV |
| 未校验上传文件 / 旧版缺少标记的事件 | USER_PROVIDED / UNVERIFIED | 实际方法 / UNVERIFIED | 不因文件扩展名或 source=video 就宣称真实识别 |

JSON、时间轴、证据弹窗、洞察和 Markdown 均保留区分。兼容旧的 `simulated` 字段；没有伪造历史事件来源。旧报告如需新标签，应重新处理/分析。

## 5. 大模型 Adapter 的验收范围

发现并修复了“所有服务都要求 Key”的问题。现在支持：

- `LLM_PROVIDER=ollama`：本机 Ollama 的 OpenAI-compatible `/v1/chat/completions`，允许免密，裸服务地址自动补 `/v1`；必须显式配置已存在的模型名。
- `LLM_PROVIDER=openai`：OpenAI 或兼容端点；本机 loopback 免密服务可使用空 Key，远程模式仍要求凭据。
- 不将全局远程 OPENAI_API_KEY 自动转发到无关本机服务；显式 LLM_API_KEY 按用户配置使用。
- JSON Schema、证据 ID 与 hypothesis 状态校验保持有效；失败不静默替换成成功的规则报告。

验收分开记录：

| 检查 | 结果 |
|---|---|
| 本机 HTTP 传输，ollama 模式、无 Key、裸 URL | 通过；响应为 MOCK_HTTP，不是 LLM 推理 |
| 本机 HTTP 传输，openai 模式、无 Key | 通过；响应为 MOCK_HTTP |
| 本机 HTTP 传输，openai 模式、显式 Bearer Key | 通过；响应为 MOCK_HTTP |
| 虚构引用、跨 Session 证据、派生洞察充当原始证据 | 拒绝；测试通过 |
| 真实 Ollama 当前实例调用 | 未验证：127.0.0.1:11434 没有可用服务，实际返回 ConnectError |
| 真实 OpenAI 当前实例调用 | 未验证：LLM_API_KEY / OPENAI_API_KEY 未配置，按预期阻止请求 |

真实调用状态见 [Ollama 检查](../artifacts/v0.1/ollama-live-check.json)、[OpenAI 检查](../artifacts/v0.1/openai-live-check.json)。二者都没有被计为 REAL_MODEL 验收成功。

本地关闭此未验证项：按 [Windows 部署说明](WINDOWS_DEPLOYMENT_V0.1.md) 配置后运行 `scripts/check_llm.py`，以 `status=passed`、合法非空洞察与引用为标准。仅端口可连接、协议 mock 通过或 model list 非空都不够。

## 6. 洞察证据追溯

产品引用测试使用单独的 **SIMULATED 人工文本 Session**：`4436df25a55d43339764d1b65ef177f6`，没有把真实参考录音冒充消费者反馈。

| 产品洞察 | 处理方式 | 原始引用数 |
|---|---|---:|
| 腰部舒适与固定 | RULE_BASED | 2 |
| 重量与耐久体验 | RULE_BASED | 1 |
| 助力表现 | RULE_BASED | 1 |
| 穿戴与易用性 | RULE_BASED | 1 |

所有引用均能在同 Session 的原始 utterance 中找到，`raw_text` 与 `evidence.quote` 一致，导出的 Markdown 含对应 ID。加上真实参考报告共检查 **6 个引用**，均通过；视频事件的截图路径也逐条读取成功。

真实录音事件还能回放原始音频，真实视频事件能查看图片并回放 MP4；人工样例只提供原始文本，不声称存在相应真人录音。派生 `AI_analysis` 不得被当作下一条原始消费者观测循环引用。补充证据会使旧报告和派生结论失效。

证据：[逐项审计 JSON](../artifacts/v0.1/evidence-audit.json)、[模拟产品报告](../artifacts/v0.1/simulated-product-report.md)。

**引用完整性不等于语义结论已证实。** 规则建议来自模板，LLM 即使引用合法 ID，也仍需研究员检查其结论是否被原话支持。当前没有真实 C3 受试者资料、总体人群统计或产品改进实验结果。

## 8. 本轮修复及关闭剩余项的方法

仅做验收所需修正：

1. 免密 Ollama / 本机兼容接口不再被统一 Key 检查拦截；防止全局远程 Key 误发给本机服务。
2. 给已有事件、反馈和报告补充 input_origin / processing_method；基础行为、主题和模板建议明确 RULE_BASED。
3. 报告增加同 Session 和原始证据保护；派生洞察不能充当原始证据。
4. 静态资源版本化，长来源标签在界面改成可读文字并保留原始编码；完整响应式检查通过。
5. 重载后回显实际时间偏移，避免“分析用了偏移但页面显示 0”的误导。
6. 修复添加标签时函数名与原活动标签变量的冲突；真实推理回归复测通过。
